# 客户现有 DataWorks 梳理

客户在 DataWorks 上的全部任务（仓库根目录 `DATAWORKS.zip`，三个工作空间：数据中台 / 数据平台 / 业务工厂）。目标：从 ODS 到 ADS 治理，并与 PFT3.0 数仓（`dw-dict/`）对齐、同步维护。

## 运行

```bash
python3 dataworks/audit.py
```

只用 Python 标准库，直接读 zip，不需要解压。

## 文件

| 文件 | 内容 |
|---|---|
| `parse.py` | 解析导出包：每个节点的类型、调度（cron、实例方式、重跑、超时）、依赖、产出，SQL 读写的表，数据集成任务的读端 / 写端（数据源、表、列、增量条件） |
| `audit.py` | 诊断规则，生成问题清单与明细 |
| `docs/问题清单.md` | 问题汇总（按级别、类别），每条有说明和治理建议 |
| `output/<编号>.csv` | 每个问题的明细（涉及的节点、表、字段） |
| `output/节点清单.csv` | 全部 1,509 个节点：路径、类型、工作流、cron、读写表、上游依赖 |

## 诊断口径

- **Hive 表**：SQL 节点 `INSERT` / `CREATE TABLE AS` 的目标，以及写端为 Hive 的同步任务目标；写端为 MySQL / Oracle / SelectDB / ClickHouse 的算「回流目标表」。
- **分层**：按表名前缀判断（`ods_` / `s_` / `src_` 记为 ODS，`dwd_`、`dim_`、`dws_`、`ads_`），客户目录名不作依据。
- **缺依赖**：节点读的表在包内有周期产出任务，但该任务不在这个节点的上游依赖链（含间接依赖）里；一次性表（`_o_f` / `_o_i`）与已暂停的产出不计。
- **多任务写同一表**：多个节点写同一批分区才计；按不同静态分区值或按表名 / 数据域等动态分区各写各的（如增量登记表）不计。
- 只看导出包内的任务；包外的查询方（BI、接口、即席查询）需结合访问日志确认，尤其是「没人用的表」。
