# 景区票务行业报告：取数方案

基于标准化数仓（`dataworks/sql/`）出一份对外 / 对政府的行业报告，例如《2026 年国庆假期景区票务消费报告》《2026 年上半年景区票务行业报告》。

本文给出报告结构、每个指标的口径、样本规则、取数逻辑、校验和安全要求。可运行的 SQL 在 `dataworks/sql/report/industry_report.sql`，结果写入报告指标竖表 `ads.ads_opr_industry_report_metric`，画图和写报告都直接用这张表。

演示稿：`dataworks/report_demo/index.html`（模拟数据，由 `build_demo.py` 按同一套样本规则生成竖表后渲染）。

---

## 一、先定三件事

| 问题 | 结论 | 影响 |
|---|---|---|
| 数据代表谁 | 票付通平台合作景区的交易，是**平台样本**，不是全行业 | 标题与口径声明写「基于票付通平台 N 家景区样本」。不出「全国景区门票总收入」这类外推数，除非另做加权外推并说明方法 |
| 报什么期 | 年度 / 半年 / 季度 / 节假日专题（元旦、春节、清明、五一、端午、中秋、国庆） | 节假日用 `dim_opr_holiday_period_f` 的放假区间。对比期取「去年同一假期」，春节按农历对齐。两期天数不同时比较**日均** |
| 给谁看 | 对外发布 / 文旅主管部门 / 内部经营 | 对外：只出聚合数，景区不具名（授权的除外），小样本格子抑制。内部：可下钻到景区 |

## 二、报告结构与指标

| 章节 | 回答的问题 | 指标 | 维度 | 标准表 |
|---|---|---|---|---|
| S1 市场总览 | 市场多大、增长多少 | 预订票数、预订金额、订单数、购票人数（去重）、日均票数、票均价、退票率、核销率 | 全部 / 可比景区；逐日趋势 | `ads_ord_scenic_trade_overview_di` |
| S2 供给结构 | 增长来自哪类景区、市场是否集中 | 各类型 / 等级 / 省份的票数占比与增速；活跃景区数；CR10、HHI | 景区类型、等级、主题、省份 | 同上 + `dim_prd_scenic_df` |
| S3 客群画像 | 谁在出游 | 到访游客的客源距离（本市 / 省内跨市 / 跨省）、年龄段、性别、同行人数、团散占比 | 客源地、年龄、性别、同行人数 | `ads_cus_scenic_traveler_profile_di` |
| S4 预订行为 | 怎么决策、何时下单 | 提前预订天数分布、下单时段分布 | 提前天数段、小时 | `ads_ord_scenic_pre_booking_di`、`dws_ord_scenic_ticket_trade_hrs` |
| S5 渠道结构 | 票从哪里卖出去 | OTA / 分销 / 直销占比，各下单渠道（小程序、窗口、自助机 …）占比 | 渠道大类、下单渠道 | `ads_ord_scenic_channel_di` + `dim_sup_member_df`、`dim_trf_channel_f` |
| S6 履约与客流 | 玩得怎么样、挤不挤 | 核销率、峰值承载率（峰值在园 ÷ 最大接待量）、承载率 ≥ 80% 的景区日占比 | 景区类型、节假日第 N 天 | `dws_trf_scenic_inout_hrs` + `dim_prd_scenic_df` |
| S7 价格 | 花多少钱 | 票均价、价格带（免费、0–50、50–100、100–200、200+ 元）票数占比 | 价格带、景区类型 | `ads_ord_scenic_trade_overview_di` |
| S8 区域 | 哪里热 | 省份 / 城市票数与可比增速、热门目的地 TOP | 省、市 | 同上 |
| 附：二次消费（可选） | 门票之外 | 停车车次与停留时长、零售客单价 | 景区类型 | `ads_opr_parking_di`、`ads_opr_retail_di` |

## 三、指标口径

全部沿用标准口径字典（字典页「指标口径 · 口径字典」）。报告里需要额外说明的有下面这些。

| 指标 | 口径 | 注意 |
|---|---|---|
| 预订票数 / 金额 | 按**下单日**统计；已支付（含现场支付），含之后取消的；金额 = 实际售价 × 原始票数，单位元 | 报告写「预订」，不写「销售」。取消在退票率里体现 |
| 到访 / 核销 | 按**验证日**统计 | 与预订不是同一批订单：节前预订、节中到访 |
| 购票人数 | 取票人证件号哈希去重。区间去重用日位图合并：`BITMAP_COUNT(BITMAP_UNION(buyer_bitmap))` | 不能把日人数相加（旧系统各表各算，重复计） |
| 票均价 | 预订金额 ÷ 预订票数 | 0 元票（免费预约）单独成「免费 / 0 元」价格带，计入票数不拉低均价 |
| 退票率 | 取消票数 ÷ 预订票数 | 同期比口径，不追踪同一批订单 |
| 核销率 | 验证票数 ÷ 预订票数 | 节假日专题建议用「游玩日在假期内的订单的核销率」（`ads_ord_scenic_pre_booking_di` 按游玩日） |
| 客源距离 | 游客客源市 = 景区所在市 → 本市；同省 → 省内跨市；否则 → 跨省 | 客源地优先级：团单 > 手机号段 > 证件地区（DWD 统一规则） |
| 年龄段 / 性别 | 由证件号出生年、性别位解析（ODS 已脱敏，只保留这几位） | 非身份证（护照、港澳通行证）记「未知」，报告中注明未知占比 |
| 渠道大类 | 一级分销商对接 OTA 或下单渠道为淘宝 / 飞猪 → OTA；无分销商或买家为普通用户 → 直销（景区自有渠道）；其余 → 分销 | 规则在 SQL 的 `channel_group` |
| 承载率 | 当日小时级在园人数峰值 ÷ 景区最大接待能力（`reception_capacity_qty`） | 只统计填了接待能力的景区，并注明样本数 |
| 集中度 | CR10 = 票数前 10 景区份额之和；HHI = Σ(份额²) × 10000 | 只出数值，不出头部景区名单 |

**时间对齐**

- 节假日：本期取 `dim_opr_holiday_period_f.start_date ~ end_date`，对比期取 `last_year_period_code` 对应的去年区间。例如 2026 国庆 10/1–10/7 共 7 天，2025 国庆中秋 10/1–10/8 共 8 天，所以总量和日均都要给。
- 常规期间：对比期取 `dim_opr_period_f.ly_start_date_no ~ ly_end_date_no`（去年公历同期）。按星期对齐时用 `dim_opr_date_f.last_year_same_day_date`。
- 逐日趋势图：横轴用「假期第 N 天」（`dim_opr_date_f.holiday_day_no`），本期与去年同一假期按第 N 天叠加。

## 四、样本规则

1. **剔除测试**：`test_flag = 0`。标准模型已统一：票 / 景区 / 供应商任一为测试，订单即为测试。
2. **异常冲量**：报告期内任一天票数 > 该景区近 90 日日均 × 20 且 > 5000 张，标记 `outlier_flag`。人工核查（团购冲量、补录、系统重推）后决定是否剔除，剔除清单附在底稿里。
3. **可比样本（同店口径）**：两期都有预订的景区为可比景区。
   - 增速类结论以可比口径为准。
   - 规模类结论用全部口径。
   - 两套数都出（`sample_type = ALL / COMPARABLE`），避免把平台新接入景区算成行业增长。
4. **最小样本抑制**：任一格子景区数 < 5 或游客数 < 1000 时 `suppress_flag = 1`，报告不展示，或合并为「其他」。这防止通过细分维度反推出单个景区的经营数据。
5. **样本覆盖说明**：报告附录写明样本景区数、各类型 / 省份分布、可比景区数及其票数占比。可比景区占比 < 70% 时，增速结论要加限定语。

## 五、取数逻辑（按步骤）

完整 SQL 见 `dataworks/sql/report/industry_report.sql`。参数为 `report_code`、`report_start/end`、`base_start/end`。

**Step 0 参数**：节假日报告直接从时间表取。

```sql
SELECT h.start_date AS report_start, h.end_date AS report_end, b.start_date AS base_start, b.end_date AS base_end
FROM dim.dim_opr_holiday_period_f h
JOIN dim.dim_opr_holiday_period_f b ON b.holiday_period_code = h.last_year_period_code
WHERE h.holiday_period_code = '2026_national_day';
```

**Step 1 样本景区 `rpt_scenic`**
- 取 `dim_prd_scenic_df` 中的正式景区，带上类型、等级、省市、接待能力。
- 算两期票数，标出 `comparable_flag` 和 `outlier_flag`。

**Step 2 逐日交易 `rpt_trade`**
- 读 ADS 日表，两期一次读出，打上 `period = CUR / BASE`，剔除异常景区。
- 后面所有章节都从这一个视图聚合，保证各章口径一致。

**Step 3 各章指标**
- 规模类：`SUM(IF(period = 'CUR', x, 0))` 和 `SUM(IF(period = 'BASE', x, 0))` 一次扫描同时出两期。
- 结构类（占比）：先按维度聚合，再用 `SUM(...) OVER (PARTITION BY dim_type)` 求占比，占比合计 100%。
  - 多个维度用 `LATERAL VIEW STACK` 展开成行，一次扫描出全部维度。
- 去重人数：用位图合并，不累加日值。
- 集中度：`sc_share` 视图在聚合内部排名，只输出 CR10 / HHI。
- 承载率：`dws_trf_scenic_inout_hrs` 小时在园先按景区合并闸机组，取当日最大值，再除以接待能力。

**Step 4 写竖表**：`ads.ads_opr_industry_report_metric PARTITION (report_code)`。
- 同比：规模类为增长率（%），占比 / 比率类为百分点差。
- 景区数 < 5 自动抑制。

**Step 5 校验**：见第六节。全部通过才出图。

**Step 6 出图与写作**：竖表直接导入 BI 或 Excel 底稿。每个结论在底稿里注明来源行（`section_code + metric_code + dim_value`），便于复核。

## 六、出报告前的数据校验

| 校验 | 方法 | 阈值 |
|---|---|---|
| 总分一致 | 各景区类型 / 各省份票数之和 = 总量 | 完全相等 |
| 占比合计 | 每个 `dim_type` 的占比求和 | 100% ± 0.1 |
| 与订单明细对账 | 报告期 `SUM(order_sale_amt)` 对比 `dwd_ord_order_di` 同期已支付金额 | 差异 < 0.5% |
| 与业务系统对账 | 抽 10 家头部景区，与景区后台报表核对预订票数 | 差异 < 1% |
| 同比异常 | 任一格子 \|同比\| > 200% | 人工复核原因（新接入、停业、冲量）后写入备注 |
| 未知占比 | 年龄、客源地「未知」占比 | > 20% 时在图注说明 |
| 样本覆盖 | 可比景区票数 ÷ 全部票数 | < 70% 时增速结论加限定语 |

```sql
-- 例：占比合计校验
SELECT section_code, metric_code, dim_type, sample_type, SUM(cur_value) AS total_share
FROM ads.ads_opr_industry_report_metric
WHERE report_code = '${report_code}' AND metric_code LIKE '%_share' AND metric_code <> 'cr10_share'
GROUP BY section_code, metric_code, dim_type, sample_type
HAVING ABS(SUM(cur_value) - 100) > 0.1;
```

## 七、安全与合规

- 报告只读 ADS / DWS 聚合表。个人信息在 ODS 已脱敏（手机号、证件号只留前缀 + SHA256），报告链路接触不到明文。
- 景区不具名。榜单只出类型、地区；要列具体景区，须取得景区书面授权。不出单一商户的金额、票数。
- 小格子抑制（第四节第 4 条）。区域下钻到区县时样本不足的合并为「其他」。
- 对外数字一律四舍五入到合理精度：票数取万张，金额取万元，占比取 0.1%。
- 每期报告的参数、样本清单、剔除清单、竖表分区都保留，便于事后审计和复算。

## 八、产出物与排期（以节假日专题为例）

| 时间 | 事项 |
|---|---|
| T（假期最后一天） | — |
| T+1 | 日调度完成，ADS 数据就绪 |
| T+1 上午 | 跑 `industry_report.sql`，人工核查异常冲量清单 |
| T+1 下午 | 校验（第六节）通过，导出图表底稿 |
| T+2 | 报告初稿；数据与业务方复核 |
| T+3 | 定稿发布 |

**产出物**
- 报告指标竖表（`report_code` 分区）。
- 图表底稿 Excel：每张图一个 sheet，标注来源行。
- 口径附录：样本说明、指标口径、时间对齐、剔除规则。
- 样本与剔除清单（内部留存）。

## 九、可以继续加深的方向

- **外推到全行业**：用文旅部门公布的 A 级景区名录做分层（等级 × 省份）权重，把平台样本加权外推。外推方法要在附录说明，误差区间单独列出。
- **新客 / 复游**：用 `dim_cus_tourist_df.first_visit_date` 区分首游、复游游客，可回答「回头客占比」。
- **客源 × 目的地流向**：客源省 × 景区所在省矩阵，可画跨省流动图。注意抑制小格子。
- **OTA 评分**：`ads_trf_ota_platform_di` 的外部服务评分可作为体验章节的补充，单独标注来源为外部采集。
