# lakehouse

PFT3.0 数仓（文旅票务）资料与数仓字典展示页。

## 打开字典页

`dw-dict/dist/index.html` 是单文件静态页，双击用浏览器打开即可，也可以放到任意静态服务器。

| 模块 | 内容 |
|---|---|
| 总览 / 分层 / 表清单 / 字段 | 已按改造后的字典展示：ADS 保持日粒度，按周期写死的指标列合并为日字段（762 列 → 326 列；比率存分子分母、去重存位图）；6 张 DWS 补去重位图列；新增时间表 dim_opr_period_f 和节假日区间表，日期维表补 7 个字段。表清单可「只看改造」；DDL 补上分区子句 |
| 指标口径 | 「指标目录（按口径）」一行一个口径；DIM / DWD / DWS / ADS 四个页签列出该层全部字段（粒度键黄色标出，可按类别筛选），每个字段都有指标名；DWS 口径字典、ADS 指标字典覆盖全部指标字段（页签上有覆盖检查）；入口链到周期展开后的 26,523 个业务指标 |
| ADS 指标体系 | ADS 只存日数据，查询时关联时间表按统计周期汇总：当日、本周/上周、本月/上月、本季/上季、本半年/上半年度、本年/上年度、近7/30/90日、近半年、近1年、节假日、自定义区间；派生出本期值、日均、上期值、环比、去年同期值、同比、周同比、占比。含业务指标清单（每条带取数 SQL）、日粒度 DDL 与查询模板，完整清单导出为 `dw-dict/dist/ADS指标体系.xlsx` |
| 表详情 ·「加工逻辑」 | 每张 DWD / DIM / DWS / ADS 表（含实时）的加工 SQL，按字段清单的「加工 / 来源」「上游字段」生成；标注直接翻译 / 规则翻译 / 待确认字段数，可一键定位待确认行 |
| 调度与治理 | 调度工作流、质量规则、总线矩阵、质量体检、待确认事项（原页面未展示的 5 个工作表） |
| 核对报告 | 对客户交付字典的自动核对结果（同时输出 [`docs/核对报告.md`](docs/核对报告.md)），逐条复核客户「质量体检」自评；「改造版复核」用同一套规则核对改造后的字典，列出仍需客户决定的项 |

```
  build.py   读 Excel → 生成 dist/index.html、dist/*_改造版.xlsx（改造后的完整字典，改动行标黄）、dist/ADS指标体系.xlsx 与 docs/核对报告.md
  checks.py  核对规则（命名规范、源库 DDL 对照、血缘/口径/ADS 交叉校验、指标聚合方式分类）

  dwd/ dim/ dws/ ads/  Spark SQL / Hive，INSERT OVERWRITE … PARTITION (travel_date='${bizdate}')
  flink/            实时 DWD / DWS：Flink SQL（CDC 源 → StarRocks，维表 Lookup Join，1 分钟窗口）
  starrocks/        实时 ADS：StarRocks 异步物化视图（每分钟刷新）

  规范/       数仓命名规范
  source/    业务系统设计文档（HLD、数据库 DDL、核心模型、应用架构、价格模型）

```

## 改造版字典（dist/*_改造版.xlsx）

在客户原 Excel 基础上的改动，改动行标黄，第一页「改造说明」逐表列出：

- **ADS**：按周期写死的列合并为日字段；指标字典按查询指标登记，另登记 160 个分子 / 分母 / 位图存储字段；「来源 DWS」取实际上游表；
- **DWS**：去重类补 `*_bitmap` 列，SUM 上卷改 BITMAP_UNION；口径字典补登记 5 个位图口径，修正落地表登记错误（A082 / A083）；
- **DIM**：新增 `dim_opr_period_f`、`dim_opr_holiday_period_f`，`dim_opr_date_f` 补 7 个字段；
- **字典一致性**（核对报告里客户原有的问题）：189 张离线表补登记分区字段 `travel_date`；按字段级血缘补全 132 处「上游表」并同步「下游表」；补齐上游字段缺字段名的 6 处；
- **质量规则**：ADS 改造表上引用旧周期字段的规则，能对应到日字段的改写 88 条、对应不上的删除 96 条，按新结构补 66 条（日字段非负、分子 ≤ 分母、波动、时间表完整性等）；
- **调度**：年调度加入节假日区间表与统计周期时间表（含质检节点）；**待确认事项**补 7 项改造相关事项。

用同一套核对规则复核改造版：原版 11 类问题，改造版剩 3 类（两份设计文档字段不一致、1 个字段命名、时间字段用 STRING），都需要客户决定，未擅自修改。

## 加工逻辑说明

`sql/` 下 176 个脚本由 `dw-dict/etl_gen.py` 生成，每个文件开头写明粒度、来源和字段翻译情况：

- **直接翻译**：加工说明是「表.字段 / 改名 / ÷100 / 按键关联」，原样转成 SQL；
- **规则翻译**：前后差（LAG）、JSON 展开、状态变更时间、聚合 where 条件、修饰词条件（如 渠道类型=小程序 → `channel_type='MP'`）等；
- **待确认**：加工说明是业务描述（递归层级、证件号映射、定价规则计算等）或引用了上游不存在的字段，SQL 里该行带 `-- 待确认：原说明`，给出可运行的占位写法，上线前需人工补齐。

脚本结构（不写嵌套子查询，每一步是一个有名字的 WITH 逻辑块，便于阅读和修改）：

- **DWD / DIM**：主表一个块（ODS 增量拆成 `xxx_rn` 编号 → `xxx_latest` 取最新两步）、每张关联表一个块（`xxx_latest` / `xxx_dim` / `xxx_cur` 当前版本 / `xxx_hist` 历史版本 / `xxx_count` 预聚合），最后 `INSERT … SELECT … FROM 主表块 LEFT JOIN 关联块`；拉链表再接 `src` → `src_hash` → `his` 三块做闭链 / 开链；
- **DWS / ADS**：每个来源一个 `src_xxx` 预聚合块 → `all_src` UNION ALL 合并 → （需要补维度名称时）`merged` 汇总 → 关联 `xxx_cur` 维度块输出；
- **性能**：每个块只读用到的列、先过滤分区再关联；被关联的 ODS 增量表先按主键去重（避免关联后行数翻倍）；码表 / 配置类小维表加 `/*+ BROADCAST(...) */`；多来源先预聚合再 UNION ALL，不用多表 FULL JOIN；单一来源不再做第二次聚合；
- 实时 DWD 的 Flink SQL 保持单层（维表时态关联 `FOR SYSTEM_TIME AS OF` 需要直接引用表）。

参数：`${bizdate}`（YYYYMMDD）、`${bizdate_dash}`（yyyy-MM-dd）、`${bizdate_prev}` / `${bizdate_prev_dash}`（前一天），周报 / 月报用 `${last_week_*}` / `${last_month_*}`。
全部脚本已用 sqlglot 做过三项检查：语法（Spark / StarRocks 方言；Flink 专有语法替换后检查）；最外层输出列的名称和顺序与字段清单一致（INSERT 按位置写入）；以字段清单为表结构，逐个校验脚本引用的每一列都真实存在。
统计周期时间表 `dim_opr_period_f` 的 SQL 已在 DuckDB 上用 2024–2026 年日期实际执行，17,536 行非节假日周期与 Python 区间算法逐行一致。
